# Architecture and project principles

New to the codebase? There is one native app, a set of reusable file-management
modules, and a shared home for window appearance and motion. The map below
should help you find the right place for a change without rebuilding something
another feature already uses.

Traverse is a native macOS file explorer by Respawn Studios. The direct edition
supports Apple Silicon and Intel on macOS 15 or later, with a separate package
for each architecture. Original project code is licensed under GPL-3.0-only;
pinned third-party dependencies keep their own notices.

## Source organization

| Directory | Responsibility |
| --- | --- |
| `App/MacExplorer/Application` | App-scoped operation, connection, editor and update owners |
| `App/MacExplorer/Browser` | AppKit workspace, panes, navigation, selection and commands |
| `App/MacExplorer/Features` | Feature-specific controllers and native/SwiftUI presentation |
| `App/MacExplorer/Shared/Presentation` | Common window chrome, placement, materials, sizing and motion |
| `Packages/ExplorerKit/Sources` | UI-free domain models and platform adapters |
| `Packages/ExplorerKit/Tests` | Reusable behavior, integration and failure regressions |
| `Workers` | Native storage-scanner source |
| `Vendor` | Pinned dependency source, licenses and provenance |
| `Distribution` | Edition configuration, release history, notices and packaging inputs |
| `tools` | Supported development, dependency and release commands |

The Xcode project is generated by `tools/generate_project.py`. Keep the ordinary
source graph and existing modules; do not create another app target or copied
source tree for a routine change. Add a domain module only when a concrete
behavior and a useful boundary justify it.

## Ownership and responsiveness

AppKit owns the browser and native command/focus behavior. SwiftUI supplies
suitable panels inside the same shared presentation system. Native UI stays out
of reusable domain modules. A view delegates file work to the existing owner;
it does not implement copying or network mutation in a button callback.

Blocking filesystem, database and network work runs off the main actor with
bounded concurrency. Async syntax alone does not make work nonblocking. A result
must still belong to the current session, selection and view before presentation.
Cancellation ends owned work and releases readers, scopes and callbacks.

Pane visits retain independent navigation and selection. App-scoped owners keep
accepted transfers, history and connection lifetimes independent of a pane's UI.
The shared window and theme layer is the place for changes that should apply to
multiple tools. See [browser behavior](BROWSER_DESIGN.md) and
[file operations](FILE_OPERATIONS.md).

## Access and privacy

The direct edition uses an explicit local-user access policy and a separate
application-data namespace and update feed. A broader filesystem policy does not
override macOS privacy controls, filesystem permissions or a remote account's
rights. Other editions retain their own capability and access checks.

Browsing and analysis are metadata-first. Opening, editing, hashing, copying,
previewing and archiving read file bodies for the requested operation. Passive
browsing does not authorize content indexing, inference or an implicit upload.
Do not put names, paths, contents, passwords or arbitrary error descriptions in
technical diagnostics. Local crash captures and their editable sharing
projections are distinct. See [Privacy](../PRIVACY.md) and
[Security](../SECURITY.md).

## Reliability and contribution

Preserve originals through validated publication, keep conflicts explicit, and
report denied, partial and uncertain outcomes honestly. An older saved record
must not acquire newer permissions or recovery semantics merely because the app
was updated. Feature completion includes ordinary-app integration and the
relevant complete workflow, not just a passing detached experiment.
