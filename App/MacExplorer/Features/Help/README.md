# Help

HelpCenter.swift presents What's New, App Logs, Updates, Get Help, Support Traverse
and About through the shared native tool navigation. BundledNotices.swift reuses
one reader/window implementation for third-party notices and the bundled GPLv3
license. SupportDetails.swift supplies a reviewable diagnostic snapshot.
ReleaseNotes.generated.swift remains at the app root and is generated by the
release-history tool.

CommunitySupportView.swift is the optional development-support page.
CommunitySupportLinks.swift admits only release-owned HTTPS destinations and
never substitutes a paid studio pass for voluntary support. The application
owner in ApplicationCommunitySupport.swift presents this existing Help page only
for an explicitly configured public launch, after setup and when the browser is
idle. SupportReminderPreferences in ExplorerCore owns its local per-release
history; BrowserSettings persists it. No payment or user-file state participates.

## Local crash reports

`ApplicationCrashReports.swift` owns one background worker and the shared native
tool window; `CrashReportsView.swift` presents only editable shareable text.
`CrashReportStore.swift` reuses `BrowserSnapshotFile` for a private, durable
catalog, with a five-record count and 4 MiB encoded aggregate cap. Removing a
record replaces the acknowledged catalog, including that native payload; it is
not secure erasure or removal of macOS's separate reports. Full or invalid state
pauses new capture rather than knowingly replacing unresolved data.

`NativeCrashCapture.swift` confines the pinned PLCrashReporter instance to that
worker. Recovery reads the exact private pending leaf with a bounded no-follow
descriptor, retains its complete data and typed projection, then rechecks the
leaf before removal. No Swift callback runs in the signal handler. The vendor
patch, source hashes and normal-launch byte-limit configuration are verified by
`tools/build_crash_reporter.py`; app and framework dSYMs stay with the exact
release. Do not invoke the upstream aggregate packaging scripts.

The UI-free `LocalStorage/Diagnostics/CrashReport.swift` allowlists versions,
signals, frames and image identities. Native paths, registers and free-form
exception text have no sharing fields. The reviewed text remains editable;
`CrashReportRedaction` is only a bounded privacy aid. Copy, new-file export and
GitHub opening require the user's explicit action. The browser URL contains a
short disclosed summary, never native capture bytes or the full report. No token,
automatic POST or automatic backend submission is included.

The direct-release choice is local capture enabled by default for useful first-
crash recovery, with a clear next-launch preference and no upload. Setup and
published privacy text disclose the raw local capture. Source implementation
does not establish real-crash, OS-reporter coexistence or installed acceptance.
See the [privacy guide](../../../../PRIVACY.md) for user-facing boundaries.

Updates shares one page and application lifecycle across the private and
prepared public direct editions. Only private beta shows invitation/Keychain
controls. Public checks are optional and default off; signing, downloading,
active-work postponement and workspace restoration stay in the common owner.
The public endpoint is prepared source, not a deployed service.

App Logs uses the existing background `DiagnosticRecorder`; the view never
reads log files directly. Follow Operation searches typed trace links across
retained pages and shows all stages, even when the starting entry was found
through Warnings and errors. Export offers either all retained events or the
selected operation and its linked steps. A missing/expired operation creates no
report; cancellation and incomplete history remain visible. No paths, names,
passwords or file contents are added by correlation or export.

Operation Recovery uses the selected journal identity as another entry into
that same graph. The returned job identity is linked by the shared operation
worker; no per-window log-file reader or stored path-to-trace lookup is added.
This identifies recorded events, not a committed filesystem outcome.

Ordinary operation Results can open the reviewed job's logs directly. Its
opaque trace is captured with the transient result, including queued transfers;
a later job or menu action cannot substitute its own trace. This grants no
retry, recovery or filesystem authority. The ordinary generated Help flow
checks Copy, retained Undo, operation export, privacy, writer failure and
minimum-window controls at normal and150% interface size. Recordings remain
separate evidence of rendered pages rather than mutation qualification.

These are folders within the same App module, not additional packages. Consult App/README.md and docs/engineering/README.md from the repository root.
